Line-height scale (text)

Four steps for text. The display type's line-heights (0.8 to 1.05: the name, the page title, the tagline, the numerals) are deliberately not tokens: each is optical tuning of Doto, and one shared value would flatten it. Each sample below is set in its own token's line-height, so you can see the spacing; the value is read from the stylesheet.

Tracking scale (letter-spacing)

Five steps: two negative ones for big type, three positive ones for capital labels. 0 and a single 0.04em figure caption stay as written. Values are read from the stylesheet.

03 · Hard shadows

The token is the size only (the shadow falls right and down by that much). The colour is chosen where it is used: box-shadow: var(--shadow-l) var(--shadow-l) 0 var(--ink);

04 · Motion

Hover a track to feel it. Each ball travels the same distance; only the token changes. The hero entrance, the arrow button and the old toggle switch have their own timings on purpose.

Page transition: the card-to-title morph

When you click a project card, its headline flies into the project page's big vertical title (and back again with the breadcrumb). It is a cross-document view transition: the browser morphs one named element on the old page into the element with the same name on the new page. The timing is the pair above (--t-base, --ease-soft), so it adds no new token. Everything lives in css/transitions.css; to add a project, add one line to each of its two lists and put data-project="name" on the project page's <main>. Two things to remember: a name must be unique on its page (a duplicate silently cancels the whole transition), and it only runs over http(s), never from a file:// address. Browsers that cannot do it simply load the page normally, and reduced motion switches it off. See it on webdesign-test.html (open it from http://localhost).

06 · Components

Text link: .text-link

Put the class on any text link. The underline follows the text (ink on light grounds, cream on dark ones); an icon is chosen from the address (an arrow for another page here, a square arrow for another site, an envelope for email, a file for any address ending in .pdf, the brand marks for GitHub, LinkedIn and Instagram); on hover a yellow highlight swoops in from the left, the text turns ink and the underline fades. The caption under each ground reads the live contrast of the underline against it. The one exception is the footer's three social links, which add .text-link--social for the signature magenta underline (last sample below). A link without that class always follows the text.

Quotes: .quote

Three voices, one family, each with its own job: small for evidence inside a story, big for a statement, card for praise from a named person. Every quote is a <figure class="quote"> holding a real <blockquote> and a <figcaption> for the attribution. A blockquote carries no look of its own; the voice is a class. The attribution is one recipe for all three: --fs-xs, tracked caps, bold name, written — <strong>Who</strong>, role, colour inherited from the ground. Use <figcaption>, never a bare <footer> or <main>: this stylesheet styles those for the site, and a bare one turns into a miniature site footer (found 2026-10-23).

Small: .quote--small. Centred like the big quote, but small: Source Code Pro Light, 1.1 to 1.5rem, 42 characters wide and balanced, with 40px above and below. Used on the TNECD pain points. (It once had an orange bar on the left and was called .quote--bar.)

on a dark ground: the quote and the attribution take the ground's cream

Big: .pull-quote. One big quote with its attribution, centred, with generous empty space around the pair. Source Code Pro Light at --fs-quote, 26 characters wide, balanced. The space above and below is --quote-space, 200px by default (a deliberate negative-space gesture); the specimens here set it to 24px so the page stays compact. Used on the About page and at the end of the TNECD case study.

Card: .quote--card. A panel with a Doto quote mark hanging over its top edge. Add .panel and a corner (.panel--cut-tl or .panel--cut-tr); the colours come from the panel variables (paper with a magenta shadow by default). --qm-size sets the size of the quote mark, which hangs 0.38em above the card, so leave that much room above it. Used on the About page (two cards). Each sets its own colours with three variables, --panel-bg, --panel-ink and --panel-shadow (set the ink too: the card's own text colour is ink): the left card is purple with cream text and a mint shadow, the right card is teal with cream text and an orange shadow. Both faces are dark, so the pair is told apart by hue and shadow, not by brightness (cream on purple 7.9:1, cream on teal 7.3:1).

Panel: .panel

A block of colour with one cut corner, a slight tilt and a hard shadow. Set it with variables (--panel-bg, --panel-ink, --panel-shadow, --tilt, and --panel-offset for a bigger shadow); pick the corner with .panel--cut-tr or .panel--cut-tl. Padding and hover belong to the page. Project card: section.featured-project-card, and its colour cycle

Colour, ink, tilt and corner come from the card's position (:nth-child(6n+N)), so six cards show the whole cycle. The pill, dome and cut corners are real. Positions use the live page grid, so resize to see it stack.

Proportions (900px and wider). Two dials set the card widths. The large cards (1 and 4) are 90% of their columns minus both dials; their narrow partners (2 and 3) are 100% plus both, so each pair trades width at its inner edge and the gutter between them never changes. --nudge is 30px at 1440 wide (it scales down at 2.08vw) and --shave is 20px (1.39vw). The narrow cards take the shave as side padding (--card-pad plus half the shave each side) rather than as plain width, so their text column, line wraps and height stay as they were. Plain extra width made them a line shorter, which pulled the row below up by as much as 26px. Set --shave to 0px to undo; --card-pad (clamp(26px, 3vw, 44px)) is the padding of every card.

Card copy. A card says what the project is and what it achieved in one sentence (the TNECD card is the model), then one Tools line (a single bullet, .gold-color-font marker). A link may sit on its own line under the sentence (for example “View project specs on GitHub”, with its tracking kept). The title is the project's canonical name, and the card, the project page's tab title, its big title and the breadcrumb all use the same words (for example TNECD.com Website Redesign and DRØM Marketing and Print). The home page and the category pages use the same sentence for the same project.

09 · House rules

  1. Tokens, not raw values. Colours, type sizes, text line-heights, tracking, shadow sizes and speeds come from the :root tokens. (The one exception is the display type's line-heights, which are optical tuning of Doto.) A new raw number needs a reason.
  2. Components, not context. A link is a link because it wears .text-link, not because of the paragraph it sits in.
  3. No new inline CSS unless it is truly one-off. If two pages want it, it belongs in the shared stylesheet.
  4. Measure, then change, then measure. Every refactor wave compares computed styles before and after (headless Chrome); only the intended differences may appear.
  5. Warn on contrast. Anything under 4.5:1 for small text gets flagged before it ships (this page does the arithmetic live).
  6. One wave, one commit, one annotated tag so any wave can be rolled back alone.
  7. Keep the stylesheet map current. When a page's data-2017 or data-1986 list changes, update the table in section 07 (“Stylesheets: which files each page loads”) in the same wave.
  8. The captain approves before anything is edited or committed; nothing is pushed without his order.
