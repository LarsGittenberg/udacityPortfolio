03 · Hard shadows

The token is the size only (the shadow falls right and down by that much). The colour is chosen where it is used: box-shadow: var(--shadow-l) var(--shadow-l) 0 var(--ink);

04 · Motion

Hover a track to feel it. Each ball travels the same distance; only the token changes. The hero entrance, the arrow button and the old toggle switch have their own timings on purpose.

Page transition: the card-to-title morph

When you click a project card, its headline flies into the project page's big vertical title (and back again with the breadcrumb). It is a cross-document view transition: the browser morphs one named element on the old page into the element with the same name on the new page. The timing is the pair above (--t-base, --ease-soft), so it adds no new token. Everything lives in css/transitions.css; to add a project, add one line to each of its two lists and put data-project="name" on the project page's <main>. Two things to remember: a name must be unique on its page (a duplicate silently cancels the whole transition), and it only runs over http(s), never from a file:// address. Browsers that cannot do it simply load the page normally, and reduced motion switches it off. See it on webdesign-test.html (open it from http://localhost).

06 · Components

Text link: .text-link

Put the class on any text link. The underline follows the text (ink on light grounds, cream on dark ones); an icon is chosen from the address; on hover a yellow highlight swoops in from the left, the text turns ink and the underline fades. The caption under each ground reads the live contrast of the underline against it. The one exception is the footer's three social links, which add .text-link--social for the signature magenta underline (last sample below). A link without that class always follows the text.

Button: .btn

The ink button: a hard shadow that grows on hover, an arrow that draws itself. Its shadow is orange by default. On the amber, orange and mint cards (1, 2 and 6) the shadow is magenta instead, because orange vanishes against the first two and is faint against mint (chosen with a variant switcher). Button shadow: orange (default) or magenta (cards 1, 2 and 6)

The shadow colour is chosen by the card's position in the cycle (.flex-container-child-projects:nth-child(6n+1), (6n+2) and (6n)), not by a class, so it applies to a .btn inside those three cards (the amber, orange and mint ones). Each tile below is drawn from the real computed values of that card's button, and shows how the other colour would fare on the same ground. Anywhere else, the shadow is chosen with a class: .btn--orange or .btn--magenta (see the two-by-two below). The shadow colour is one variable, --btn-shadow, which those classes and the cards' position rule set.

The buttons, two by two: face and shadow

Two faces, two shadows. The ink face is for light grounds (the cards); the paper face, .btn--on-dark, is for dark grounds (night, night-deep, ink), because the ink button would vanish there. Each face takes either shadow: .btn--orange or .btn--magenta. The paper button turns gold on hover, lifts, and draws its arrow; the ink button flips to paper. Hover them.

Quotes: .quote

Three voices, one family, each with its own job: small for evidence inside a story, big for a statement, card for praise from a named person. Every quote is a <figure class="quote"> holding a real <blockquote> and a <figcaption> for the attribution. A blockquote carries no look of its own; the voice is a class. The attribution is one recipe for all three: --fs-xs, tracked caps, bold name, written — <strong>Who</strong>, role, colour inherited from the ground. Use <figcaption>, never a bare <footer> or <main>: this stylesheet styles those for the site, and a bare one turns into a miniature site footer (found 2026-10-23).

Small: .quote--bar. A quiet orange bar on the left, Source Code Pro Light. Used on the TNECD pain points.

on a dark ground: the bar and the attribution take the ground's cream

Big: .pull-quote. One big quote with its attribution, centred, with generous empty space around the pair. Source Code Pro Light at --fs-quote, 26 characters wide, balanced. The space above and below is --quote-space, 200px by default (a deliberate negative-space gesture); the specimens here set it to 24px so the page stays compact. Used on the About page and at the end of the TNECD case study.

Card: .quote--card. A panel with a Doto quote mark hanging over its top edge. Add .panel and a corner (.panel--cut-tl or .panel--cut-tr); the colours come from the panel variables (paper with a magenta shadow by default). --qm-size sets the size of the quote mark, which hangs 0.38em above the card, so leave that much room above it. Used on the About page (two cards, each with its own colours).

default colours: paper, magenta shadow, no tilt (a page sets --tilt and its own colours)

Panel: .panel

A block of colour with one cut corner, a slight tilt and a hard shadow. Set it with variables (--panel-bg, --panel-ink, --panel-shadow, --tilt, and --panel-offset for a bigger shadow); pick the corner with .panel--cut-tr or .panel--cut-tl. Padding and hover belong to the page. The project cards share the same rule (a card is a panel with a border, a hover lift and its own six-colour cycle), so the cycle below sets the same --panel-bg, --panel-ink and --panel-shadow.

09 · House rules

  1. Tokens, not raw values. Colours, type sizes, shadow sizes and speeds come from the :root tokens. A new raw number needs a reason.
  2. Components, not context. A link is a link because it wears .text-link, not because of the paragraph it sits in.
  3. No new inline CSS unless it is truly one-off. If two pages want it, it belongs in the shared stylesheet.
  4. Measure, then change, then measure. Every refactor wave compares computed styles before and after (headless Chrome); only the intended differences may appear.
  5. Warn on contrast. Anything under 4.5:1 for small text gets flagged before it ships (this page does the arithmetic live).
  6. One wave, one commit, one annotated tag so any wave can be rolled back alone.
  7. The captain approves before anything is edited or committed; nothing is pushed without his order.
